# 03 Demo 架构（Phase 1）

## 1. 目标与分层

Demo 把三条主线合成一个日文 480×480 UI：A 运动感知与 HMI、B 离线音频/边缘 AI、C 互动游戏（默认“傾き迷路”）。关键设计决定：**一份可移植的 C 核心**，Host 与设备只在“传感器输入 / 效果输出”两端各自适配。

```
 ┌────────────── Host 预览（已实现，模拟器已验证）────────────┐   ┌─ 设备适配（3a 已烧录；3b 计划）─┐
 │ host/exp_sim_source.c  合成传感器（SIM 标记常显）          │   │ BSP: IMU/磁力计/ES8311/触摸/电池 │
 │ host/game_module.c     引擎 ABI v1 模块                    │   │ device_adapter.c（尚不存在）      │
 └───────────────┬───────────────────────────────────────────┘   └───────────────┬──────────────────┘
                 │  exp_sensors_t（推入）          exp_effect_t（拉出：声音/震动）  │
                 ▼                                                                 ▼
        ┌─────────────────────────── exp_app（可移植 C 核心，已编码/已编译/模拟器已验证）─────────────────┐
        │ exp_fusion  Mahony AHRS + 磁力计校准        exp_audio  FFT256 / 24 频段 / VAD（经典 DSP，非 AI）│
        │ exp_maze    迷宫模型 + BFS 演示机器人       exp_app    页面、导航、闲置/展示循环、效果队列      │
        │ exp_page_{home,motion,audio,game,device}    exp_ui / exp_gfx / exp_text（自带文字与形状层）   │
        └───────────────────────────────────────────────────────────────────────────────────────────────┘
                 渲染到 Raylib Lite 的 RGB565 表面（480×480）
```

## 2. 接口契约

* **推入**：平台每个 tick 调用 `exp_app_set_sensors()`，传入快照。快照里每个传感器有状态（`EXP_SENS_OK/SIMULATED/ABSENT/FAULT` 类语义），核心不会把缺失当成零值使用。
* **拉出**：核心把“请求播放声音 / 请求震动”放进队列，平台通过 `exp_app_pop_effects()` 取走执行。核心本身不接触硬件。
* **单一所有者线程**：`exp_app.h` 注明所有调用来自同一任务；生产者在其他任务需先排队。
* **确定性时钟**：核心使用 `now_ms += dt`，不读系统时间，便于测试复现（`exp_app_state_hash`）。

## 3. 数据真实性规则（强制）

| 数据 | Host 预览 | 设备（计划） |
|---|---|---|
| 姿态/磁力计/麦克风 | 合成，界面上永久显示 `SIM` 标签 | 仅真实读数；失败显示“未检出/故障” |
| 堆/PSRAM 数值 | 默认 `--` | 真实读取，否则 `--` |
| 推理耗时 | `--`（仅 DSP 耗时在有时钟时显示） | 真实测量，否则 `--` |
| AI/唤醒词 | “実機モデル検証待ち”，**不产生任何识别结果** | 在模型实际跑通前保持同样文字 |
| RF 状态 | 固定 “RF Verification Pending” | 同上，直到真实测量 + 日本法规结论 |

没有随机或预录的“假识别”。Host 的模拟麦克风只合成音频信号（音调/类语音/噪声/扫频），VAD 是对这些信号的真实 DSP 结果。

## 4. 模块说明

| 模块 | 内容 | 状态 |
|---|---|---|
| `exp_fusion` | Mahony AHRS：俯仰/横滚绝对（6 轴），偏航相对；**完成完整磁力计校准后**才启用 9 轴。校准用 min/max 硬铁 + 各轴比例，要求 8 个卦限各 ≥10 样本、跨度 ≥40 µT、样本 ≥60。磁力修正投影到垂直轴，避免污染俯仰/横滚；静止时学习陀螺偏置。pitch 为顶边仰角（−90..90），roll 为绕顶边的全圆旋转（−180..180] | 已编码/已编译/模拟器已验证 |
| `exp_audio` | 256 点 FFT、24 个对数频段、峰值保持、噪声底跟踪、VAD（能量 + 语音带比例 + 低频比例）。这是**经典 DSP，不是 AI** | 已编码/已编译/模拟器已验证 |
| `exp_maze` | 7/9/11 格迷宫、孔洞、60 秒限时、坠落扣分、BFS 演示机器人；静态存储，进入/退出游戏不分配内存 | 已编码/已编译/模拟器已验证 |
| `exp_app` | 页面状态机、触摸队列、效果队列、闲置/展示循环、JSON 状态、状态哈希 | 已编码/已编译/模拟器已验证 |
| Host 适配 | `host/exp_sim_source.c`、`host/game_module.c`；**永不链接进固件** | 模拟器已验证 |
| 设备适配 | 3a：显示、触摸、整屏推送（`firmware/main/device_main.c`）。3b：传感器/音频/电池/扩展槽/效果执行 | 3a：已编译，**设备已验证**（显示、触摸有响应、帧耗时）；3b：**计划**（未编码） |

## 5. 展示循环（逻辑见 09）

任意无操作 45 秒回到首页；首页再停留 30 秒进入展示（attract）巡回：动作 12 秒 → 音频 12 秒 → 游戏演示（到结果后 3.5 秒，最长 50 秒）→ 首页 6 秒 → 循环。任何触摸立即结束展示，且**这一次触摸只用于唤醒并返回首页，不触发按钮**。展示期间声音与震动被抑制；一般震动被限制在 5–100 ms。进行中的游戏局不会因闲置被强制返回。

## 6. 为什么不用 LVGL / GSP

* GSP 当前无法从云端下载验证（见 02）。
* 只依赖引擎表面可保持 Host/设备同一份渲染代码，并让布局检查器（重叠/溢出/触摸尺寸/缺字）在无设备的情况下工作。
* 这是 Phase 2 的权衡，不是对 GSP 的否定；Phase 3 前若用户希望切换到 GSP，需要重新评估许可与大小。

## 7. 内存与大小（仅事实）

* `exp_font_data.c` 约 1 MB 源文件（字形位图）。0.3.0 构建：`mosaico_experience.bin` 0x8c6f0 字节（≈ 575 KB），最小 app 分区 0x177000，剩余 63%（构建输出）。运行时的堆/PSRAM 实际占用**未读取**（3a 不显示这些值）。
* 主体 C 代码约 1.28 万行（含生成的字体表则更多）。

| 项 | 做法 | 状态 |
|---|---|---|
| 绘制层 | `exp_surface` 实现 `mosaico_raylib_fast.h` 的子集；Host 上与官方引擎比对 7 个画面共约 161 万像素，**0 个不同** | 模拟器已验证（Host） |
| 字节序 | 固件构建开启 `EXP_SURFACE_SWAP_BYTES`，帧缓冲存面板需要的大端 RGB565；Host 比对确认“字节对调的构建 == 普通构建逐像素对调”，错误像素 0 | Host 已验证；**设备已验证**（对调前颜色错乱，对调后正常） |
| 帧缓冲 | 两个 480×480×2 B 的 PSRAM DMA 缓冲（64 字节对齐），双缓冲：传输上一帧时绘制下一帧 | 设备已验证（`wait` 由约 24 ms 降到约 8 ms） |
| 时间步进 | 主循环按实际经过时间调用 `exp_app_update`，每步仍是 1/30 s（测试用的步长），一次最多补 3 步（≤ 100 ms）。此前固定每帧 1/30 s，导致帧慢时动画慢放 | 设备已验证（切页明显变快，用户观察） |
| present 任务 | `esp_lcd_panel_draw_bitmap()` 阻塞约 8.4 ms，所以帧提交放进核心 0 的独立任务（队列深度 2 + 计数信号量），绘制线程只等空闲缓冲；`wait` 降到约 0.4 ms | 设备已验证（照片读数，08 §7） |
| 传感器接入 | 传感器任务在**触摸初始化完成之后**启动（BSP 的 I2C 总线首次创建不是线程安全，见 10 B31）；IMU 数据超过 300 ms 未更新即不再标记有效；陀螺仪取两次读取之间的平均值（应用按帧积分）；标志位只在有真实数据时置位；电池读数需通过合理性检查（2500–4600 mV，≤100%）且新于 6 s | 设备已验证（04 §7） |
| 屏幕日志 | 三连点任意角落（2 秒内）打开/关闭；点上半屏向上翻、下半屏向下翻；点传感器行区域把“turned”角度清零；无触摸时自动打开。**展出前 `EXP_DBGLOG=0`** | 设备已验证 |
| 调试叠加层 | 屏幕顶部一行：`now`（上一帧）、`max`（最近 60 帧最慢）、`d`（绘制平均）、`wait`（等待屏幕平均），单位 ms。**展出前必须关闭**（`EXP_TIMING_OVERLAY=0`） | 设备已验证（读数来自照片） |

| 无线 | 固件不调用任何 Wi-Fi/BT/ESP-NOW/802.15.4 API；链接内容审计见 06 §7 | RF已审计(静态)；**RF Verification Pending** |
